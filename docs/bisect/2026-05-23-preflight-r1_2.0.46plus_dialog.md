## 1) 执行前环境前提（必须全部满足）

### 设备
- 仅使用同一台目标设备完成本轮全部候选点验证（禁止中途更换设备）。
- 设备电量充足，避免测试中断；供电方式在本轮内保持一致。
- 固件刷写工具链版本固定，不在本轮中临时升级/降级。

### 网络
- 使用稳定网络，测试期间不切换 Wi-Fi/热点。
- 网络可访问所需云端服务（语音识别/对话服务）且延迟无明显异常。
- 若出现大面积网络抖动或服务不可达，立即暂停，不判定 good/bad。

### 账号
- 全程使用同一账号、同一权限态（不切换账号、不重新授权为另一身份）。
- 账号 token/登录状态在每个候选点前确认有效。

### 音量
- 扬声器音量固定在预设档位（记录具体档位/百分比）。
- 测试期间不得临时调节音量；若必须调节，需整轮重测并标注原因。

### 麦克风
- 麦克风输入链路正常（无静音、无遮挡、无外接设备状态漂移）。
- 测试环境噪声可控，尽量保持同一位置、同一说话距离。

## 2) 每个候选点切换前后必须记录的证据

### 切换前（Before）
- 当前目标候选标识：`commit hash / tag / candidate 名称`。
- 本次刷写来源与文件校验信息（至少文件名 + 校验值或等价标识）。
- 环境快照：网络状态、账号状态、音量档位、麦克风状态。
- 测试脚本版本：`round_id + protocol_id` 明确写入记录。

### 切换后（After）
- 实际运行标识：设备上报版本号/构建标识/commit 信息（能取到几项记几项）。
- 启动与就绪证据：开机日志关键时间点、ready 时间戳。
- 三轮真实对话证据：
  - 第 1 轮（事实问答）提问文本与回答摘要；
  - 第 2 轮（上下文承接）提问文本与回答摘要；
  - 第 3 轮（继续追问）提问文本与回答摘要；
- 原始证据索引：日志文件名、录音/录像文件名、时间戳区间。

## 3) good / bad / flake 最小记录要求

### GOOD（最小要求）
- 三轮真实对话全部成功，且第 2/3 轮体现上下文承接。
- 至少 1 份可回溯原始证据（日志或录音/录像）可支撑结论。
- 明确写出“为何 GOOD”（不是仅写 ready/idle）。

### BAD（最小要求）
- 明确失败轮次与失败类型（ASR 失败/上下文丢失/答非所问/中断等）。
- 至少 1 份原始证据定位到失败时刻。
- 明确写出“为何 BAD”，禁止仅凭主观印象。

### FLAKE（最小要求）
- 至少出现一次“同候选、同流程、结果不一致”。
- 记录重复次数（如 3 次中 1 次失败）与每次结果。
- FLAKE 不得强行归并为 GOOD/BAD；需标注“待复测”。

## 4) artifact-only 风险提示

- 若仅能确认 candidate artifact，而无法闭环到唯一 commit，则该点结论必须标注 `artifact-only`。
- `artifact-only` 仅用于现象分层与优先级排序，不可直接作为“回归根因提交”定论证据。
- 任何基于 `artifact-only` 的阶段结论，必须附带“映射未闭环”声明。

## 5) 必须停止、不得继续判结论的情形

出现以下任一情况，立即停止本轮并标记 `STOP`：
- 设备身份或固件身份无法确认（运行标识缺失或互相矛盾）。
- 网络/云服务明显异常，导致对话链路不可用或结果失真。
- 账号状态异常（掉线、权限变化、token 失效）且未恢复。
- 音量/麦克风环境发生不可控变化，已破坏可比性。
- 关键证据缺失（无法提供三轮记录或无法回溯原始日志/录音）。
- 同一点连续复测仍高度不稳定，且无法区分环境问题与版本问题。

> STOP 后只能做“环境修复与重建基线”，不得继续推进 bisect 结论。
> 本轮遇到 STOP 时，只能记录“中止/待复测”，不得继续判定 GOOD/BAD。

## 2) 每步最少证据（Minimum Evidence）

每个候选点（含 HEAD）至少记录以下证据，缺一不可：

### A. 目标与身份
- 目标标识：`commit hash / tag / candidate 名称`
- 刷写来源标识：文件名 + 校验值（或等价唯一标识）
- 运行身份回读：版本号/构建号/commit（能取几项记几项）

### B. 三轮真实对话证据（核心）
必须有完整三轮，且第 2/3 轮体现上下文承接：
1. 第 1 轮：事实问答（Q/A 摘要）
2. 第 2 轮：承接上一轮（Q/A 摘要）
3. 第 3 轮：继续追问（Q/A 摘要）

### C. 原始证据索引
- 至少 1 份可回溯原始证据：日志或录音/录像
- 记录文件名 + 时间戳区间

### D. 判定结论
- 仅允许：`GOOD` / `BAD` / `FLAKE`
- 必须写明“为何如此判定”（失败轮次与类型，或上下文承接成功点）

---

## 3) 判定红线（禁止替代判定）

- **禁止**用 `ready/idle`、仅唤醒成功、仅在线状态来代替三轮真实对话判定。
- `ready/idle` 只能作为“设备就绪辅助信息”，**不能**直接判 GOOD。
- 若缺少三轮对话证据，只能标记为“证据不足/待复测”，不得判 GOOD/BAD。

---

## 4) STOP 条件（出现任一项立即停止）

出现以下任一情况，立即标记 `STOP` 并终止本轮，不得继续推进 bisect 结论：

1. 设备身份或固件身份无法确认（运行标识缺失/冲突）
2. 网络/云服务异常导致对话链路失真或不可用
3. 账号状态异常（掉线、权限变化、token 失效）且未恢复
4. 音量/麦克风/环境发生不可控变化，破坏可比性
5. 关键证据缺失（三轮记录缺失，或无原始日志/录音可回溯）
6. 同一点连续复测高度不稳定，无法区分环境问题与版本问题

> STOP 后仅允许环境修复与基线重建；不得强行继续给出 GOOD/BAD 结论。

## 5) artifact-only 记录写法（强制模板）

当“candidate artifact ↔ commit”未闭环时，必须显式写 `artifact-only`：

```md
- point: <候选点标识>
- mapping: artifact-only
- candidate: <candidate 名称>
- inferred_commit: <推定提交/范围；若无填 unknown>
- evidence: <metadata/release-notes/git 线索>
- confidence: low|medium|high
- note: 该结论仅用于现象分层，不作为根因提交定论
```

说明：
- artifact-only 可用于排序与阶段判断；
- 不可直接当作“回归根因提交”最终证据；
- 阶段结论必须附“映射未闭环”声明。

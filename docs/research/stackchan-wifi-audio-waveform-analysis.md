# StackChan Wi-Fi Audio 波形量化分析

日期：2026-08-05

## 目的与边界

本分析用机器可重复的指标比较真实 MIC1/MIC2 首轮录音，主观听感仅作为辅助标签。输入 WAV 已经过固件采集、Wi-Fi、PC Dock、24→48 kHz 处理和 VB-CABLE，因此可以证明最终链路中的波形问题，但不能恢复固件已经丢弃的原始 DMA 位，也不能单独定位问题发生在 ES7210、ESP32 DMA、网络还是 Windows。

可复现工具：`tools/wifi_audio_analysis/analyze_wav.py`

输入：

- `tmp/wifi-audio-physical-mic1-48k-20260805-233909.wav`
- `tmp/wifi-audio-physical-mic2-48k-20260805-234824.wav`

机器可读结果：`docs/research/assets/wifi-audio-waveform-20260805/waveform-analysis.json`

诊断图：

## 方法

- 20 ms 短时 RMS，10 ms hop，用于观察包络和近数字静音区段。
- 8192 点 Hann 窗频谱，2048 点 hop，用于谱图、频带占比、谱质心和谱平坦度。
- 300--3400 Hz 作为窄带语音结构参考；它不是语音可懂度分数。
- 20 ms 帧 RMS 不超过 2 PCM counts 时标为“近数字静音”。这种帧主要由 `-1/0/+1` 组成，与普通环境静音的模拟底噪不同。
- 检查相邻样本重复、偶/奇样本重复、16 个 bit plane、低/高字节取值和削波，以寻找重采样、字节错位或位宽截断迹象。
- 没有时间对齐的干净参考录音，因此不计算 STOI/PESQ；强行计算会产生没有物理意义的分数。

## 结果

| 指标 | MIC1 | MIC2 | 解释 |
| --- | ---: | ---: | --- |
| RMS | `154.01` (`-46.56 dBFS`) | `146.51` (`-46.99 dBFS`) | 总体电平接近且偏低；放大后仍不可辨，故不是单纯播放音量问题 |
| Peak | `2941` (`-20.94 dBFS`) | `3771` (`-18.78 dBFS`) | 两路均未削波 |
| 300--3400 Hz 能量占比 | `55.59%` | `39.84%` | MIC1 含更多语音频带结构；MIC2 更偏低频环境/干扰 |
| 0--80 Hz 能量占比 | `3.61%` | `8.73%` | MIC2 低频占比约为 MIC1 的 2.4 倍 |
| 谱平坦度 | `0.1526` | `0.2150` | MIC2 更接近宽带噪声；数值越高通常越噪声化 |
| 近数字静音帧占比 | `12.88%` | `4.07%` | 两次录音均有成段供数中断/静音填充特征，MIC1 更严重 |
| 近数字静音区段 | `21` 组，最长约 `340 ms` | `6` 组，最长约 `240 ms` | 足以造成断续和调频感，但不能解释非静音区段的持续雨噪 |
| 相邻样本相等 | `30.22%` | `25.81%` | 明显受 24→48 kHz 处理或缓冲行为影响；并非原始 48 kHz 麦克风基线 |
| Windows ch0/ch1 相关系数 | `0.999990` | `0.999989` | VB-CABLE 两声道是同一 mono 输出的近似复制，不代表同时取得两颗物理麦 |
| 低字节不同取值数 | `256/256` | `256/256` | WAV 阶段未呈现低字节恒零的简单左移错误 |
| 高字节不同取值数 | `23/256` | `28/256` | 与总体幅度较低一致；不能据此恢复原始 ADC 位对齐 |

50/60 Hz 及前八次谐波附近约占 MIC1 `6.00%`、MIC2 `9.46%`。该指标使用有限频率分辨率，只能说明候选线谱较强，不能在没有硬件同步测量时直接归因为市电耦合。

## 可确认结论

1. MIC1 和 MIC2 的最终 PC 波形都不合格，但不是完全相同：MIC1 含更多随时间变化和语音频带结构，MIC2 更平稳、更低频且更噪声化。这与“MIC1 有模糊人声、MIC2 主要是环境音”的辅助听感一致。
2. 两次录音都存在近数字静音区段，证明最终链路还有独立的连续供数问题。与录音相同生命周期的 Dock 日志持续报告 `sequenceGaps=0`，VB-CABLE player 报告 `underflows=0`，因此这些区段不是已知的 WebSocket 丢帧或播放器 underrun；更可能是设备发送的 PCM 本身已接近数字静音，或当前计数器尚未覆盖的缓冲层行为。它会制造断续/调频感，但不是非静音区段雨噪的完整解释。
3. Windows 双声道几乎完全相关，所以当前录音不能用于双麦相位、时延或波束形成评估。
4. 两路无削波，等峰值放大仍无法恢复可辨语音，因此“只需要提高播放音量”被排除。
5. WAV 的低字节使用完整，没有发现可直接由后处理纠正的整字节恒零错误；但 16-bit WAV 不能排除更早阶段的 slot framing、WS/BCLK、原始 24/32-bit 对齐或错误声道问题。

## 仍需区分的故障段

- ES7210 输出前：MICBIAS、模拟前端、增益、电源/RF 耦合、MIC2 声学开孔或硬件通路。
- ES7210 到 ESP32：BCLK/WS 帧长度、Philips 一位延迟、TDM slot 到达与 DMA 打包。
- ESP32 到 Windows：短读/错误返回被忽略、10 ms 帧边界，以及当前计数器没有覆盖的缓冲行为。现有 `sequenceGaps=0` / `underflows=0` 已降低 WebSocket 丢帧和 VB-CABLE underrun 的优先级。

下一步不能再通过普通最终 WAV 唯一定位；应先完成官方配置与当前实现的真值矩阵，再选择一次能同时观察总线原始数据和最终 PCM 的高信息量实验。
